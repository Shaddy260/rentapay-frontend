# Staying up to date

RentaPay is used entirely through a web browser, whether that is a phone browser,
a desktop browser, or an installed home screen icon, so a new feature or fix is
available the moment it is deployed, without anyone needing to download or install
an update.

## Why you might see an update banner

If a tab is left open for a long time, or reopened from a home screen icon, it can
end up still running an older version of the app even after a new version has been
deployed. RentaPay checks for this automatically every few minutes while a tab is
open, and, if a newer version exists, shows a small banner letting you know an
update is available. Refreshing the page loads the new version immediately; there
is nothing to install and no account setting to change.

## Nothing is gated by when you joined

Every account, whichever role it belongs to and whenever it was created, runs the
exact same version of RentaPay as every other account, all of the time. A new
feature becomes available to everyone the moment it ships, not gradually, and not
based on how long an account has existed.

## How to check whether RentaPay itself is having a problem

If something in the app is not behaving as expected, RentaPay's public status page is
the fastest way to tell whether the problem is on our end or specific to your own
device or connection. The status page is reachable without signing in, refreshes
itself automatically, and reports on more than a dozen individual parts of the
platform separately, including sign in, payments, email delivery, SMS and WhatsApp
alerts, push notifications, file storage, background jobs such as rent reminders,
report and export downloads, support chat, the public listings page, maintenance
requests, disputes and complaints, the community board, utility submetering, and
error tracking. Each one is shown as either "Operational" or "Issue detected," with a
plain-language description of what that part of the app actually covers, so if
something is broken you can see by name which feature is affected rather than being
told only that "something, somewhere" is wrong.

When a check reports an issue, the status page also shows a short summary naming
exactly which components are affected and which everyday feature each one touches,
for example "Payments (M-Pesa) — affects making or confirming a payment." This means
that if, say, only email delivery is affected, you can trust that signing in, making
a payment, and everything else is working normally, and only emailed codes and
receipts are delayed. If the whole page cannot be reached at all, and other websites
also fail to load for you, the issue is most likely your own internet connection
rather than RentaPay.

## Update history is not published publicly

RentaPay does not currently publish a public changelog of every individual update.
Because every account always runs the same, current version, there is no "you're on
an old version, update now" scenario to warn about, which is the main reason a
changelog matters for most other kinds of software. If a specific change affects how
a feature works in a way that needs explaining, that explanation is added to the
relevant section of this guide, or communicated directly through an in-app
notification or announcement, rather than kept in a separate historical log.
